# AllDown 5.3.0

> نام جدید برنامه **AllDown** است (package و مسیر آپدیت بدون تغییر می‌ماند تا روی نسخهٔ قبلی نصب شود).

دانلودمنیجر فارسی و راست‌به‌چپ برای اندروید با دو موتور داخلی:

- **HTTP بومی:** دانلود فایل مستقیم با ادامهٔ دانلود (`Range` / `ETag`)، تلاش مجدد و نمایش سرعت.
- **رسانه:** اجرای واقعی `yt-dlp` داخل برنامه با Chaquopy؛ بدون سرور یا سرویس واسط.

سورس پروژه مستقیماً در همین مخزن قرار دارد؛ برای دریافت کد به فایل ZIP نیازی نیست.

## امکانات پایه (از 2.2.2)

- **مسیر سازگاری شبکهٔ Android:** درخواست‌های عمومی‌ای که extractor جدید yt-dlp برای آن‌ها browser impersonation می‌خواهد، در نبود `curl-cffi` دیگر پیش از شبکه رد نمی‌شوند. این مسیر برای Pornhub لازم است؛ هیچ TLS fingerprint جعلی یا دورزدن ورود انجام نمی‌شود و handler واقعی در صورت وجود همچنان اولویت دارد.
- **Instagram عمومی بدون پیام عجولانهٔ کوکی:** لینک‌های Post/Reel/IGTV استاندارد می‌شوند و اگر مسیر معمول شکست بخورد، Embed عمومی همان Shortcode برای Probe، Resolve و Download بررسی می‌شود. Format IDهای `video_versions` حفظ می‌شوند تا انتخاب کیفیت قبلی باطل نشود. محتوای خصوصی و لینک واقعاً نیازمند ورود همچنان به حساب مجاز نیاز دارد.
- **Spotify قابل‌تشخیص‌تر:** اگر Embed تغییر کرده یا در دسترس نباشد، برای آهنگ تکی از `oEmbed` استفاده می‌شود؛ یافتن Entity به Wrapper ثابت JSON محدود نیست و خطای واقعی جست‌وجوی YouTube دیگر پشت پیام عمومی «پیدا نشد» پنهان نمی‌شود.
- **Header و انتقال:** User-Agent قدیمی اختصاصی برنامه دیگر Headerهای به‌روز yt-dlp را بازنویسی نمی‌کند. Chunk پیش‌فرض ۱۶MB، Buffer ابتدایی ۱MB و ۶ اتصال Fragment است؛ هیچ Rate Limit مصنوعی فعال نیست. این تنظیمات محدودیت CDN یا اینترنت را حذف نمی‌کند.
- **تطبیق دقیق‌تر Spotify:** بررسی چند نتیجه، امتیازدهی عنوان/خواننده/مدت‌زمان و رد Cover، Karaoke، Remix، Live و نسخه‌های Speed-changing ناسازگار؛ جست‌وجوی دوم با نام کامل خواننده‌ها فقط در صورت نبود تطبیق مطمئن.
- **انتخاب کیفیت جداگانه برای هر دانلود:** لینک تکی، هر آیتم پلی‌لیست و هر آهنگ Spotify پس از Probe فهرست واقعی خودش را دارد؛ Preset ثابت از صفحهٔ افزودن حذف شده است.
- نمایش ردیف‌های Progressive، فقط‌تصویر و فقط‌صدا با Format ID، Codec، FPS، بیت‌ریت، زبان و حجم؛ فرمت‌های VP9/AV1/WebM و کیفیت‌های پایین نیز دیگر فیلتر نمی‌شوند.
- خروجی واقعی MP4/MKV/WebM و صوتی MP3/M4A/Opus/OGG/FLAC/WAV. تبدیل و استخراج صدا با FFmpeg انجام می‌شود، نه صرفاً تغییر پسوند فایل.
- جفت‌کردن صدای سازگار با فرمت فقط‌تصویر؛ برای خروجی صوتی از این حالت، تصویر دانلود و سپس حذف نمی‌شود و فقط ترک صدا دریافت می‌شود.
- ذخیرهٔ Format ID تصویر/صدا، نوع و پسوند خروجی و بیت‌ریت در صف JSON و اعتبارسنجی دوباره هنگام Resolve؛ حذف فرمت سایت باعث دانلود بی‌صدا از کیفیت دیگر نمی‌شود.
- پروکسی اختیاری HTTP(S)/SOCKS5 برای Probe، Resolve، جست‌وجو و دانلود yt-dlp، همراه با پیام‌های قابل‌عمل برای DNS، Timeout و `Errno 111 Connection refused`.
- حفظ شناسایی فرمت‌های بدون Codec در **Aparat/Pornhub**، لینک‌های Embed و localized/premium، دانلود موازی قطعات، اعلان‌های بهبودیافته و رفتار قدیمی صف برای آیتم‌های قبلی.
- نسخه‌های وابستگی استخراج پین شده‌اند: `yt-dlp 2026.10.21` و `certifi 2026.10.23`. پردازش رسانه با FFmpegKit نگه‌داری‌شدهٔ `8.1.9` (LGPL و سازگار با 16KB page) انجام می‌شود.

## سایت‌ها و لینک‌ها

علاوه بر فایل مستقیم `http/https`، موتور رسانه از سرویس‌های پشتیبانی‌شدهٔ yt-dlp استفاده می‌کند؛ از جمله:

| سرویس | لینک‌های قابل استفاده |
|---|---|
| YouTube / YouTube Music | ویدیو، Shorts و پلی‌لیست |
| Aparat | `/v/<id>` و لینک Embed/اشتراک‌گذاری |
| Pornhub | `view_video.php?viewkey=…`، `video/show` و `/embed/<id>` |
| Spotify | آهنگ، آلبوم و پلی‌لیست؛ با تطبیق متادیتا و منبع صوتی باز |
| Instagram / TikTok / X / Facebook | محتوای عمومی؛ برخی لینک‌ها به کوکی حساب خود کاربر نیاز دارند |
| Vimeo / Dailymotion / Twitch / Reddit | ویدیو و پلی‌لیست‌های پشتیبانی‌شده |
| SoundCloud / Bandcamp / Mixcloud / Audiomack | صوت و پلی‌لیست |
| Bilibili / Rumble / VK / OK.ru / Streamable | با موتور عمومی yt-dlp |
| Namasha / Filimo / Telewebion / Archive.org | بسته به نوع محتوا و محدودیت سرویس |

لینک‌های نامأنوس و بدون پسوند هم ابتدا به موتور استخراج داده می‌شوند. پشتیبانی واقعی هر صفحه به extractor آن سرویس، محدودیت جغرافیایی و وضعیت ورود بستگی دارد؛ محتوای DRM دور زده نمی‌شود.

### نکتهٔ Instagram

برای Post/Reel عمومی ابتدا extractor رسمی yt-dlp و سپس Embed عمومی همان پست امتحان می‌شود. خطای Rate Limit با نیاز واقعی به ورود یکی نیست و پیام برنامه آن‌ها را جدا می‌کند. اگر پست در مرورگر بدون Login باز نمی‌شود، fallback هم آن را عمومی نمی‌کند. لینک `/share/...` که فقط Token دارد باید توسط سرویس به پست واقعی Redirect شود و به Shortcode جعلی تبدیل نمی‌شود.

### نکتهٔ Spotify

اسپاتیفای استریم DRM ارائه می‌کند. برنامه فایل DRM را استخراج نمی‌کند؛ نام آهنگ، خواننده و مدت را از متادیتای عمومی می‌خواند و نسخهٔ صوتی منطبق را از منبع باز جست‌وجو می‌کند. چند نتیجه با عنوان، خواننده، مدت‌زمان و نوع نسخه مقایسه می‌شوند. اگر فقط Cover/Remix/Live یا نتیجهٔ مبهم پیدا شود، برنامه آن را جای آهنگ اصلی دانلود نمی‌کند و هشدار می‌دهد. بنابراین کیفیت و درستی نتیجه همچنان به متادیتا و نتایج موجود در منبع جست‌وجو بستگی دارد.

## کیفیت، خروجی و سرعت

پس از افزودن لینک، ابتدا **ردیف واقعی سایت** و سپس **خروجی همان ردیف** را انتخاب کنید. این کار برای هر عضو پلی‌لیست و هر آهنگ Spotify جداگانه انجام می‌شود. انتخاب در صف ذخیره می‌شود و برخلاف Preset، به لینک‌های بعدی منتقل نمی‌گردد.

- «ویدیو + صدا» با Remux/ادغام و بدون Re-encode تصویر ساخته می‌شود.
- «فقط تصویر» فقط برای ردیف‌های جداگانهٔ بدون صدا پیشنهاد می‌شود.
- خروجی صوتی از یک جفت DASH فقط ترک صدا را دانلود می‌کند؛ اگر منبع Progressive باشد، صدا پس از دانلود استخراج می‌شود.
- گزینهٔ «صدا • اصلی» تبدیل ندارد. MP3/M4A/Opus/OGG با بیت‌ریت انتخابی و FLAC/WAV با Encoder واقعی ساخته می‌شوند؛ FLAC بودن خروجی، افت کیفیت منبع فشرده را برنمی‌گرداند.
- Preset داخل تنظیمات فقط برای آیتم‌های قدیمی یا fallback موقع نبود فهرست فرمت است. در حالت صوتی، AAC/M4A مانند نسخهٔ قبل اولویت اول است و بقیهٔ ردیف‌ها نیز نمایش داده می‌شوند.

از تنظیمات می‌توانید دو مقدار سرعت را جدا کنترل کنید:

1. **تعداد دانلود همزمان:** تعداد آیتم‌های فعال در صف.
2. **اتصال موازی هر دانلود:** تعداد قطعات همزمان HLS/DASH در هر آیتم؛ برای Aparat و بسیاری از سرویس‌های ویدیویی مؤثر است.

مقادیر خیلی زیاد لزوماً سریع‌تر نیستند و ممکن است روی اینترنت ضعیف یا محدودکنندهٔ سرعت نتیجهٔ معکوس بدهند. مقدار پیش‌فرض ۶ برای شروع است. برای فایل‌های HTTP معمولی نیز Chunk شانزده‌مگابایتی و Buffer یک‌مگابایتی تنظیم شده و هیچ محدودکنندهٔ سرعت مصنوعی در برنامه فعال نیست. سرعت نهایی همچنان به CDN، Throttling سرویس، تعداد دانلودهای همزمان و کیفیت اینترنت بستگی دارد؛ عدد سرعت تضمینی وجود ندارد.

## محدودیت شبکه و Pornhub

Extractor جدید Pornhub درخواست صفحه را با الزام browser impersonation می‌فرستد، ولی کتابخانهٔ native مربوط در Chaquopy در دسترس نیست. مسیر سازگاری 2.2.2 این درخواست را با HTTPS استاندارد اجرا می‌کند تا خطای «no impersonate target available» مانع شروع شود. این تغییر مانند هر تست واحد، موفقیت شبکهٔ زنده را ثابت نمی‌کند و مسدودی IP/جغرافیا همچنان به شبکه کاربر بستگی دارد.

اگر خطا `[Errno 111] Connection refused` باشد، برنامه هنوز صفحهٔ سایت را دریافت نکرده و مشکل به انتخاب فرمت مربوط نیست. اتصال/VPN را بررسی کنید یا در **تنظیمات → پروکسی موتور رسانه** یک پروکسی معتبر مانند `http://127.0.0.1:8080` یا `socks5://127.0.0.1:1080` وارد کنید. مقدار خالی همان اتصال مستقیم قبلی است. پروکسی در خواندن صفحه/فرمت و خود دانلود yt-dlp اعمال می‌شود.

هیچ تست واحدی نمی‌تواند موفقیت شبکهٔ یک سرویس را روی گوشی تضمین کند. در صورت ادامهٔ خطا، پیام جدید، نوع پروکسی (بدون رمز) و لاگ دستگاه برای تشخیص لازم است.

## اعلان‌ها

- اعلان پیشرفت برای اجرای قانونی دانلود پس‌زمینه (Foreground Service) لازم است و هنگام دانلود فعال نمایش داده می‌شود.
- اعلان پایان و خطا از تنظیمات برنامه قابل خاموش‌کردن است.
- در اندروید ۱۳+ مجوز `POST_NOTIFICATIONS` لازم است. درخواست فقط یک‌بار خودکار انجام می‌شود.
- اگر اعلان دیده نمی‌شود، از **تنظیمات آریا → بخش اعلان‌ها → باز کردن تنظیمات اعلان سیستم** هم اعلان کلی برنامه و هم کانال «پایان دانلود» را بررسی کنید.
- لمس اعلان پایان، فایل ذخیره‌شده را با برنامهٔ مناسب باز می‌کند.

## کوکی‌ها

برای محتوای عمومی کوکی لازم نیست؛ در Instagram مسیر Embed عمومی نیز پیش از درخواست کوکی بررسی می‌شود. Rate Limit یا مسدودی IP به‌تنهایی اثبات نیاز به کوکی نیست. اگر سرویس برای محتوای مجاز حساب شما واقعاً ورود بخواهد:

1. از مرورگر خودتان خروجی Netscape با نام `cookies.txt` بگیرید.
2. در تنظیمات آریا، «وارد کردن cookies.txt» را انتخاب کنید.
3. فایل فقط در حافظهٔ خصوصی برنامه ذخیره می‌شود و هر زمان قابل حذف است.

کوکی معادل کلید نشست حساب است؛ آن را در Git یا برای دیگران ارسال نکنید.

## ساخت از سورس

پیش‌نیازها: JDK 17، Android SDK Platform 33 و Python 3.13 روی سیستم بیلد.

```bash
export JAVA_HOME=/path/to/jdk17
export ANDROID_HOME=/path/to/android-sdk
echo "sdk.dir=$ANDROID_HOME" > local.properties
./gradlew assembleDebug
```

خروجی Debug در `app/build/outputs/apk/debug/` ساخته می‌شود. فایل‌های APK، کش بیلد و `local.properties` در Git نگهداری نمی‌شوند.

### امضای Release (اختیاری)

```bash
cp keystore.properties.example keystore.properties
# مسیر و رمزهای واقعی را فقط در فایل محلی وارد کنید
./gradlew assembleRelease
```

`keystore.properties` و فایل‌های `*.jks` / `*.keystore` در `.gitignore` هستند. بدون این فایل، Release به‌صورت unsigned ساخته می‌شود و سورس به هیچ رمز ثابتی نیاز ندارد.
